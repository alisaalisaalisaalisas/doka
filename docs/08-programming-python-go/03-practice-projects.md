## 🐍 Проект P1: healthcheck-cluster — многопоточный health-checker (Python)

**ТЗ:** CLI-инструмент читает YAML со списком эндпоинтов и раз в N секунд проверяет их параллельно, ведёт историю состояний, шлёт алерт в webhook при смене статуса.

```yaml
# targets.yaml
targets:
  - { name: api, url: "https://api.example.com/healthz", expect: { status: 200 } }
  - { name: db, host: pg.internal:5432, type: tcp }
interval: 30
webhook: "https://hooks.slack.com/services/..."
```

**Обязательные требования:**

1. `asyncio` + `aiohttp`: 100+ таргетов без потоков на каждый.
2. Состояния с гистерезисом: `up → degraded` после 2 фейлов подряд, `down` после 5 (антифлап).
3. Экспорт метрик Prometheus `/metrics` (prometheus_client): up/down, latency histogram.
4. Конфиг через env + YAML; логи JSON; graceful shutdown по SIGTERM.
5. Dockerfile < 60 МБ + docker-compose demo.

**Критерии приёмки:**

- [ ] 100 таргетов опрашиваются за < 2с
- [ ] Антифлап проверен тестом: 1 сбой не даёт алерт, 5 подряд — дают
- [ ] Метрики скрейпятся Prometheus'ом из compose-стенда
- [ ] `pytest` покрывает логику состояний (моки сети)
- [ ] README с GIF демо и примером алерта

## 🐍 Проект P2: secret-audit — сканер секретов в git-истории (Python)

**ТЗ:** инструмент находит потенциальные секреты (AWS keys, приватные ключи, токены) во всей истории репозитория и генерирует отчёт.

**Обязательные требования:**

1. Обход истории через `git log -p --all` (subprocess) или pygit2.
2. Правила — декларативные regex-паттерны в YAML (`aws_access_key_id: AKIA[0-9A-Z]{16}`) + entropy-check для base64-строк.
3. Вывод: таблица терминал + SARIF/JSON (интеграция в CI).
4. Режим `--since` для инкрементального скана (только новые коммиты).
5. Тесты на фикстуре мини-репозитория с заведомыми секретами.

**Критерии приёмки:**

- [ ] Находит все 10 заложенных паттернов в тестовом репо
- [ ] Ложных срабатываний ≤ 20% (проверка на собственном коде)
- [ ] Инкрементальный прогон 1000 коммитов < 30с
- [ ] CI-job example в README (GitLab include)

## 🐹 Проект G1: kubectl-plugin «kstats» (Go)

**ТЗ:** kubectl-плагин (Krew-совместимый) показывает сводку по кластеру одной командой: топ подов по CPU/RAM, количество рестартов, возраст сертификатов.

```
$ kubectl kstats --namespace shop --top=5
POD                     CPU(%)   MEM(%)   RESTARTS   AGE
shop-api-7d9f...        87       62       0          3d
worker-6b8c...          12       91       4 ⚠        3d
...
⚠ worker: restarts>3 за 24h — проверить OOM (limit?)
```

**Обязательные требования:**

1. Cobra CLI: флаги `--top`, `--sort`, `--watch`, вывод json/yaml/table.
2. client-go: informer или прямой list — обосновать выбор в README.
3. Эвристики-подсказки: рестарты + лимит памяти → «вероятен OOMKill»; pending → причина из events.
4. Сборка multi-platform (Makefile: linux/darwin/arm64), goreleaser конфиг.
5. Тесты эвристик (fake clientset).

**Критерии приёмки:**

- [ ] Устанавливается как kubectl-плагин (`kubectl kstats` работает)
- [ ] Подсказка про OOM подтверждается вручную на kind-кластере
- [ ] `go test ./...` зелёный; lint golangci-lint чистый
- [ ] Бинарник < 25 МБ, старт < 500ms на 200 подах

## 🐹 Проект G2: webhook-relay — надёжный релей вебхуков (Go)

**ТЗ:** сервис принимает вебхуки (например, Alertmanager), пишет в локальную очередь (диск!), повторяет доставку с backoff в целевой URL, переживает рестарты.

**Обязательные требования:**

1. HTTP-сервер: приём любого POST → WAL-файл (append-only журнал) → ack 202.
2. Воркер доставки: exponential backoff + jitter, max attempts, DLQ-каталог для умерших сообщений.
3. Ретраи переживают рестарт процесса: очередь восстанавливается из WAL.
4. Метрики Prometheus: принятых/доставлено/в очереди/DLQ.
5. Нагрузочный тест в README: 1000 rps на ноутбуке без потерь.

**Критерии приёмки:**

- [ ] `kill -9` в момент нагрузки → после старта ни одно сообщение не потеряно
- [ ] Целевой URL недоступен → сообщения копятся, восстановились → доставлены по порядку
- [ ] Backoff виден в логах (JSON) с attempt-номером
- [ ] docker-compose демонстрация с mock-приёмником

## 🐍➕🐹 Проект PG3: infra-doctor — единый аудит стенда (Python/Go на выбор)

**ТЗ:** одна команда собирает состояние машины/кластера и выдаёт вердикт с приоритетами: что сломано, что рискованно, что дорастёт до проблемы.

Проверки (плагинная архитектура!):

| Проверка | Источник | Пример вердикта |
| :--- | :--- | :--- |
| Диски >85% / inode | df | 🔴 `/var: 91% — логи nginx не ротируются` |
| fd близко к лимиту | /proc/PID/limits | 🟡 `nginx: 4200/65535 fd` |
| systemd units failed | systemctl | 🔴 `docker.service: failed` |
| conntrack/utilization | sysctl | 🟡 `conntrack 71% от max` |
| Сертификаты <14 дней | openssl s_client | 🔴 `api.local: истекает через 9 дней` |
| K8s: PDB violations, Pending | kubectl | 🟡 `2 деплоя без PDB` |

**Обязательные требования:**

1. Плагины: каждая проверка — отдельный модуль c интерфейсом `{run() -> Finding}`; добавление проверки = один файл.
2. Severity: red/yellow/green; exit code ≠0 если есть red (для CI/cron).
3. Выводы: текст, markdown-отчёт, JSON; режим `--fix-hints` с командами лечения.
4. Идемпотентность и read-only: только чтение состояния!

**Критерии приёмки:**

- [ ] На чистой VM — все green; на VM из chaos-lab.sh (disk_fill) — красный диск
- [ ] Новый плагин пишется за ~50 строк (доказать третьим своим плагином)
- [ ] Cron-ready: работает без TTY, шлёт отчёт в файл/webhook
