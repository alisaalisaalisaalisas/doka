# 🧪 Песочница: терминал и редактор кода

> Интерактивная среда прямо на сайте: **симулятор терминала** + **редактор кода** для отработки практических заданий из handbook'а.

**Открыть песочницу: → [playground.html](playground.html)**

## Что внутри

| Компонент | Возможности |
| :--- | :--- |
| **Терминал** | ввод команд с историей (↑/↓), автодополнение (Tab), `clear`/`Ctrl+L`, цветной вывод как в реальном CLI |
| **Редактор кода** | Monaco (движок VS Code) с подсветкой YAML/HCL/Shell; при отсутствии интернета — встроенный fallback-редактор |
| **Проверка решения** | кнопка «Проверить решение» сверяет выполненные команды с целью (чек-лист ✓/✗); «Проверить код» валидирует написанное в редакторе |
| **126 сценариев** по всем темам: Linux/Bash/Git/Сети · Docker/K8s/Helm · Terraform/Ansible/CI · Prometheus/Loki/Vault/Kyverno · Kafka/RabbitMQ/PG/MySQL/Redis/CH · Istio/облака/Proxmox · **MLOps: MLflow/DVC/дрейф/GPU-Kueue/LLMOps-RAG** |

## Как работать

1. Выберите сценарий в выпадающем списке.
2. Прочитайте задание слева; кликните по файлу — он откроется в редакторе.
3. Выполняйте команды в терминале справа. Симулятор понимает команды сценария; неизвестные — подскажут нажать «Подсказки».
4. Нажмите **«Проверить решение»** — увидите чек-лист: что сделано, чего не хватает.
5. Для заданий с кодом — напишите код в редакторе и нажмите **«Проверить код»**.

!!! tip "Порядок важен"
    Симулятор запоминает **все** выполненные команды. Проверка смотрит, что нужные шаги были выполнены в этой сессии — «угадать» финальную команду не выйдет.

## Как добавить свой сценарий

Откройте `playground.html` и добавьте объект в массив `SCENARIOS`:

```js
{
  id: "my-scenario",                    // уникальный id
  title: "Название сценария",           // в списке
  level: "Middle",                      // сложность
  brief: `<b>Симптом:</b> ...`,         // описание (HTML)
  files: { "deploy.yaml": "..." },      // файлы, открываются в редакторе
  editorFile: "deploy.yaml",            // какой файл открыт по умолчанию
  editorChecks: [                       // проверка кода в редакторе
    { re: /policyTypes/, label: "есть policyTypes" }
  ],
  prompt: "ubuntu@lab:~$",
  commands: [                           // симулятор терминала
    { re: /^kubectl get pods$/, out: "NAME ...", cls: "ok" }
  ],
  solution: [                           // чек-лист решения
    { re: /kubectl get pods/, label: "посмотреть поды" }
  ]
}
```

- `commands[].re` — regex, по которому матчится введённая команда (первое совпадение побеждает);
- `cls` — цвет вывода: `ok` (зелёный), `err` (красный), `warn` (жёлтый), `dim` (серый);
- `solution[].re` — что должно быть выполнено для зачёта.

!!! note "Симулятор ≠ настоящий кластер"
    Песочница тренирует **последовательность мышления и команды**. Для реальных рук — kind/k3d-стенды из [Guided Labs](../16-guided-labs/01-lab-linux-systemd-namespaces.md).
